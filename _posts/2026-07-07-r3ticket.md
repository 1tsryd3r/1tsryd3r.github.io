## TL;DR
Bypassed an obfuscated array lookup using a logical flaw to leak the maximum array element. Modeled the subsequent large-exponent mathematical leak as a Closest Vector Problem (CVP) and used LLL lattice basis reduction to recover the random 24-bit exponent for all 16 rounds.

## Analysis of chall.py

- First off, in the `get_num()` function, we can see that the variable `part` can only ever evaluate to two values: `0` or `1`.

```python
def get_num(nums, index):
    if index > len(nums) - 1:
        return 0
    result = 0
    for i in range(len(nums)):
        part = 1
        for j in range(len(nums)):
            if j == i:
                continue
            part *= (index - j) // (i - j)
        result += part * nums[i]
    return result
```

- Here, `nums` is an array of 128 randomly generated 16-bit integers, and `index` is an integer we input.
- If we look at the inner loop, for any index we input, `j` will eventually equal `index` (since `j` loops through the entire length of the array). When `j == index`, the numerator `(index - j)` becomes `0`. As a result, `part` becomes `0` and stays `0` for all subsequent iterations of the inner loop.
- However, in the specific case where the outer loop reaches `i == index`, the inner loop will completely skip the `j == index` iteration because of the `if j == i: continue` check. This means the fraction `(index - j) // (i - j)` will always evaluate to `(index - j) // (index - j)`, which is exactly `1`.
- So, `result` remains `0` for every iteration of the outer loop except when `i == index`, where it computes `result = nums[index]`. Ultimately, this entire obfuscated function simply returns the number present at `nums[index]`.
- Moving to the 16 challenge rounds:

```python
for round in range(16):
    print(f"{round + 1}/16")
    x = secrets.randbits(24)
    h = sum([num**x for num in nums])
    print("challenge =", str(h)[:64])

    check = int(timed_input("x = ", ANSWER_TIMEOUT))
    if check != x:
        print("You lose...")
        exit()
```

- The script calculates `h` as the sum of every number in the array raised to a random 24-bit exponent `x`: $h = \sum_{i=1}^{128} n_i^x$. We are given the higher 64 decimal digits of `h`, truncating the rest.
- The critical flaw here is that because `x` is so large (up to $2^{24}$), `h` is entirely dominated by the highest number in the `nums` array, which we will call `m`.
- To prove this mathematically, assume the second highest number is `m-1`. The ratio of their terms in the sum is $((m-1)/m)^x$, which simplifies to $(1 - 1/m)^x$. Because `x` averages around $2^{23}$ and `m` is at most 65535, $(1 - 1/m)^x \approx e^{-x/m} \approx e^{-128} \approx 0$. The smaller terms are infinitesimally small.
- This allows us to accurately approximate `h` as: $h \approx c \cdot m^x$
- Here, `c` is the multiplicity, the number of times `m` occurs in the `nums` array. Because `nums` is populated with 128 random 16-bit integers, the chances of the absolute maximum number being generated more than once are statistically insignificant, making `c = 1` almost a certainty. Since there is no modulo applied to this equation, the massive exponentiation leaks the data cleanly.

## The Exploit
- Taking the base-10 logarithm on both sides of our approximated equation, we get:
  $\log_{10}(h) \approx x \cdot \log_{10}(m) + \log_{10}(c)$
- We can rearrange this into a linear equation targeting zero, making it perfect for the LLL reduction algorithm: $x \cdot \log_{10}(m) + \log_{10}(c) - \log_{10}(h) \approx 0$ <br>
*(Note: Since we established `c = 1`, $\log_{10}(c) = 0$, meaning that term drops out entirely).*
- To run this lattice reduction, we must find `m`. Because the `nums` array is generated *per connection* (not per round), if we find `m` once, we can solve all 16 rounds on that same connection.
- By utilizing the vulnerability in `get_num`, we can leak `nums[0]`. Statistically, we have a 1/128 chance that the element at index `0` happens to be the maximum number `m` for the entire array. While connecting 128 times doesn't ensure success, looping the connection will practically guarantee we hit the correct configuration within a few hundred attempts.
- Once we leak a candidate for `m`, we construct an embedding lattice in column-major form, using a massive constant `K` ($2^{200}$) to scale the floating-point logarithms into integers without losing precision:

$$
\begin{bmatrix}
K \log_{10} m & K & K \log_{10} h \\
1 & 0 & 0 \\
0 & 1 & 0 \\
0 & 0 & W
\end{bmatrix}
$$

- When LLL reduces this lattice, it searches for the shortest possible vector. If our leaked `nums[0]` is indeed the maximum element `m`, LLL will successfully balance the equation, returning a vector containing our target `x` in the range $0 \le x < 2^{24}$.
- We submit this `x`, pass the first round, and repeat the lattice reduction for the remaining 15 rounds using the exact same `m` to get the flag.

## Solve script

```python
from pwn import *
from sage.all import *

def solveforx(m, output):
    # Using 300 bits of precision to avoid floating point truncation
    R = RealField(300)

    output = R(output) / R(10**63)
    logm = R(m).log10()
    log_output = R(output).log10()

    K = 2**200
    W = 2**100

    # Lattice representation of: x*logm + logc - logh ≈ 0
    M = Matrix(
        ZZ,
        [[int(K * logm), int(K), int(K * log_output)], [1, 0, 0], [0, 1, 0], [0, 0, W]],
    ).T.LLL()

    for row in M:
        if abs(row[3]) == W:
            x = abs(row[1])
            if 0 <= x < 2**24:
                return x
    return None

attempts = 0
while True:
    p = remote("challenge.ctf2026.r3kapig.com", 32262, level="error")

    attempts += 1
    print(f"Attempt: {attempts}")

    # Leak nums[0] using the get_num vulnerability
    p.recvuntil(b"Which number you want to know: ")
    p.sendline(b"0")
    p.recvuntil(b"Here is what you want: ")
    m = int(p.recvline().strip())

    p.recvuntil(b"Lets play!\n", timeout=15)

    success = True

    for round_num in range(16):
        p.recvuntil(f"{round_num + 1}/16\n".encode())
        p.recvuntil(b"challenge = ")
        chal_str = p.recvline().strip().decode()

        x = solveforx(m, chal_str)

        # If lattice fails, nums[0] was not the max element
        if x is None:
            print("Trying again")
            success = False
            p.close()
            break

        p.recvuntil(b"x = ")
        p.sendline(str(x).encode())
        print(f"Solved round {round_num + 1}")

    if success:
        p.recvuntil(b"ticket: ")
        flag = p.recvline().strip().decode()
        print(flag)
        break
```
